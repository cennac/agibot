# Android 14 r20 AP6275P 0034.0041 firmware

Date: 2026-08-26

## r19 runtime isolation

r19 boots normally and downloads the MB0002 vendor-reference AP6275P firmware
without an HCI timeout. Its identity is:

```text
Size:    59,061 bytes
SHA-256: 26ae849bb70e8d8e8e7571ef78c3c516a08dfda114d605d57daacdd72aad6aee
Version: BCM43752A2 UART 37.4MHz Ampak AP6275P [0021.0023]
```

Windows explicitly reported `Discoverable=True` and `Connectable=True` for
`LAPTOP-BGDHCEIE` at `BC:6E:E2:FB:2C:2C`. Android received that controller's
BLE advertisements but received no Classic Inquiry Result, Inquiry Result with
RSSI, or Extended Inquiry Result events. Direct paging ended with
`HCI_ERR_PAGE_TIMEOUT`.

Two reversible runtime tests narrowed the failure further:

1. Android's Wi-Fi service was disabled, `wlan0` was down, and the kernel log
   already contained `WLAN OFF Done`. Removing the remaining `bcmdhd` module
   succeeded, removed `wlan0`, and did not restore Classic discovery.
2. All six r18 Classic scan properties were restored to the r16 defaults before
   a clean Bluetooth restart: interlaced scan type, Inquiry
   `0x0800/0x0012`, and Page `0x0400/0x0012`. Three complete discovery cycles
   still returned no Classic peer.

This excludes active Wi-Fi/PTA ownership and the wider r18 local scan windows
as primary causes on r19. Evidence is retained outside Git at:

```text
E:\AIPorject\101\android14-flash\validation\r19-runtime-classic-ab\
```

## Build and acceptance

Use the standard remote AOSP partition build and Rockchip `./build.sh -u`
packaging flow. Do not use a custom repacker. The normalized local release must
follow the existing dated r20 directory and filename convention.

After flashing:

1. Verify the running HCD size, hash, AP6275P identity, and `0034.0041` version.
2. Require Bluetooth initialization without HCI timeout and preserve OTP address
   `B0:02:47:43:EA:3B`.
3. Run one Windows-visible Settings discovery and require at least one Classic
   Inquiry result event.
4. If discovery remains empty, change only the six scan properties to the r16
   defaults at runtime, restart Bluetooth, and repeat once.
5. Only after Classic discovery succeeds, test one real accessory or Windows
   pairing attempt and require progress beyond `HCI_ERR_PAGE_TIMEOUT`.
6. Re-enable Wi-Fi and confirm Wi-Fi scan plus BLE reception have not regressed.

### Classic and BLE result

Windows reported `Discoverable=True` and `Connectable=True`. With the r18
wide local scan configuration, full HCI snoop recorded:

```text
Inquiry commands:                  7
Inquiry Result (0x02):             0
Inquiry Result with RSSI (0x22):   0
Extended Inquiry Result (0x2f):    0
LE Advertising Report events:    102
```

The six Classic properties were then changed at runtime to the r16 defaults,
followed by a clean Bluetooth restart. The second full snoop recorded:

```text
Inquiry commands:                  4
Inquiry Result (0x02):             0
Inquiry Result with RSSI (0x22):   0
Extended Inquiry Result (0x2f):    0
LE Advertising Report events:     75
```

Android's Settings peer list remained empty in both tests. For the reverse
direction, Android was confirmed `SCAN_MODE_CONNECTABLE_DISCOVERABLE`, but two
Windows native Classic Inquiry runs also returned no `MB0002 V2` device.

r20 therefore rejects the newer AP6275P HCD as a Classic repair. The failure
is bidirectional BR/EDR RF behavior while LE reception and the HCI transport
remain stable. Do not produce another HCD-only version. The next repair should
compare controller vendor radio/coexistence initialization against the last
known Classic-receive result on r16, or restore r16 firmware as a controlled
baseline before changing one non-firmware variable.
